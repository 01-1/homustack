# Usage dashboard

One compact page at http://127.0.0.1:8770 (loopback only; reloads every 60 s):

- % of target rate for Fable, Claude non-Fable, Codex and Outside APIs over the 5, 15, 30 and 60-minute windows. The figures come unchanged from the installed read-only producer `~/.local/bin/usage-target-rates` (the same numbers claude-usage reports). 100% means on pace. A cell turns amber at the ladder's first warning level and red at the default stop. Where the producer has no reliable figure ("inc" or "stale"), the cell shows a dimmed estimate "~N%". It is the same window math (`target_rate_window`) without the producer's coverage checks; hover for the producer's reason. Tooltips also show the soft credit inside each window. Credits are negative usage at the moment they were granted, so they leave a window as it moves past them.
- "Of total": for each category, the current weekly meter points of all accounts against the full capacity including banked resets. Both use the box policy's own units: `capacities()`, `gauges()` and account weights from `~/.config/claude-usage/boxes.toml`. An account with no current figure adds nothing and is marked `*`, so that % is a lower bound. Usage from weeks that have already reset is not counted.
- Rebase: `usage_dashboard.py --rebase` saves what is left per category to `~/.local/state/usage-dashboard/baseline.json`. It works from the usage ledger alone, read under the ledger lock. What is left is each account's capacity including banked resets, minus its last ledger meter reading. An account with no current figure, or one the ledger marks as carried from before a reset, counts as having nothing left. It also saves a marker: the last event in the ledger at that moment. From then on the view reads "Since <time>": the raw usage events the ledger appended after the marker. This goes by position, not timestamp, because a meter check that commits late can stamp its events earlier than the rebase. Those events are counted raw, with no guard exemptions or credits, out of what was left. The ledger keeps events across weekly resets. Events expire after about eight days; once the marker is gone, the view shows an error until you rebase again. Delete the file to go back to "Of total".
- % used of every CLIProxyAPI account: Claude proxy (:8318) and Codex proxy (:8317), for the 5-hour, weekly and (Claude) Fable weekly windows. These are read through `~/.local/bin/claude-usage`. They are the proxies' last stored usage headers, so they change only when an account serves a request. A window whose reset time has passed shows "reset".
- Buttons +1m, +5m and +15m. After a confirm dialog, each runs the installed `uncap 1`, `uncap 5` or `uncap 15`: credit goes only to capped categories and to the Outside API budget if it is blocked. The output appears on the page, and the usual notices go out.

Loading the page writes nothing and sends nothing to Anthropic or OpenAI; the management keys stay in the server. A button is accepted only from this page: the Origin must match, and the request must carry a random token issued when the server starts. Any local process that reads the page could still press one; `uncap` in a terminal does not allow that.

To run it as a transient user service, run `usage_dashboard.py` under `systemd-run --user --unit=usage-dashboard --collect`; stop it with `systemctl --user stop usage-dashboard`. Foreground: `python3 -B usage_dashboard.py [--port N]`.

It loads `claude-usage`, `claude_usage_boxes` and `uncap` from `$CLAUDE_USAGE_BIN` (default `~/.local/bin`), so install claude-usage first.
